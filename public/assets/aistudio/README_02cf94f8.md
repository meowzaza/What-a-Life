# ชีวิตจริงยิ่งกว่านิยาย (What a Life!) — คู่มือเริ่มต้นสำหรับ AI (AI Entry Point)

> **สำคัญมากสำหรับ AI เมื่อเปิดโปรเจกต์หรือ Remix ข้ามบัญชี:**
> โปรเจกต์นี้ผ่านการพัฒนามาแล้ว 16 รอบงาน (ถึง **Phase 3.2.3-P1** ถัดไปคือ **Phase 3.3.1**) ห้ามเดาโครงสร้างจากความจำ และ **ห้ามกวาดอ่านไฟล์สเปกหรือโค้ดทั้งหมดพร้อมกัน** เพื่อประหยัดโควต้าโทเคน ให้ปฏิบัติตามลำดับการอ่านด้านล่างอย่างเคร่งครัด

## 1. โปรเจกต์นี้คืออะไร
- **ชื่อเกม:** ชีวิตจริงยิ่งกว่านิยาย (*What a Life!*) — เกมจำลองชีวิตคนไทยร่วมสมัย (Thai Contemporary Life Simulator) แนวแซนด์บ็อกซ์ โทนเสียดสีชีวิตจริง ตลกร้าย อบอุ่นปนดราม่า **ไม่สอนศีลธรรม (No Moral Preaching)**
- **แพลตฟอร์ม:** เว็บแอปพลิเคชันเน้นหน้าจอมือถือ (`360–430 px`) พัฒนาด้วย **React 19 + TypeScript + Vite**
- **สินทรัพย์ภาพ (ล็อกห้ามแก้ไข):** ตัวละครพิกเซลพาสเทล PNG 332 ตัว (`public/assets/characters/` + `src/data/characterManifest.json`) และฉากพิกเซล 21 ฉาก (`public/assets/scenes/` + `public/assets/scenes/sceneManifest.json`)

## 2. ลำดับการอ่านเอกสาร (Context Loading Protocol)
1. **อ่านทุกครั้งที่เริ่มเซสชันใหม่:**
   - `docs/README.md` (ไฟล์นี้)
   - `docs/DESIGN.md` (แก่นเกม, กฎเหล็กวิศวกรรม, และตารางสถานะ 1 บรรทัดต่อ Phase)
2. **อ่านเมื่อได้รับคำสั่งให้ทำ Phase ใด Phase หนึ่ง:**
   - เปิด `docs/ROADMAP.md` **เฉพาะหัวข้อของ Phase ที่กำลังจะทำ**
   - เปิด `docs/CORE_BLUEPRINTS.md` **เฉพาะแม่พิมพ์ที่ต้องใช้** (เช่น เควสแตกแขนง, ฉายา, Storylet)
   - เปิดไฟล์สเปกใน `docs/specs/` **เฉพาะเลขไฟล์ที่ `ROADMAP.md` ระบุไว้เท่านั้น** (ดูสารบัญใน `docs/specs/00_index.md`)
   - เปิดไฟล์ลิสต์ยาวใน `docs/catalogs/` **เฉพาะไฟล์/หมวดที่บรรทัด "ไฟล์ที่ต้องอ่าน" ของ Phase นั้นระบุ** (เช่น `catalogs/institutions.md` หมวดการศึกษา) ห้ามอ่านทั้งโฟลเดอร์
   - ถ้าเป็นสเปก `08`–`17` ที่ยังไม่มีไฟล์ ให้ดูหัวข้อ **"วัตถุดิบ"** ของ Phase นั้นใน `ROADMAP.md` ซึ่งบอกว่าต้องดึงรายละเอียดจากหมวดไหนของ `BACKLOG_IDEAS.md`, ใช้แม่พิมพ์ข้อไหนใน `CORE_BLUEPRINTS.md`, และชนิดข้อมูลข้อไหนใน `SCHEMAS.md` ก่อนเขียนสเปก
3. **เมื่อต้องการหาชื่อไฟล์โค้ด ฟังก์ชัน หรือ Type ที่มีอยู่แล้ว:**
   - เปิด `docs/CODE_MAP.md` ก่อนเสมอ **ห้ามเปิดไล่อ่านไฟล์ใน `src/` สุ่มสี่สุ่มห้า**
4. **เมื่อต้องการเช็กว่างานไหนทำไปแล้ว หรือทำไมถึงออกแบบไว้แบบนั้น:**
   - ค้นหาด้วยรหัส Phase ใน `docs/PROGRESS.md` (ประวัติงานที่เสร็จแล้ว 16 รอบ) หรือ `docs/DECISIONS.md`

### กฎการเก็บข้อมูลลิสต์ยาว (Catalog Rule)
- ลิสต์ที่มีรายการเยอะและต้องเพิ่มบ่อย (ทักษะ, พรสวรรค์, ฉายา/ความสำเร็จ, มหาวิทยาลัย/คณะ/สาขา/ชื่อเสียง, กิจกรรม/ชมรม, เหตุการณ์, เควส, อาชีพ ฯลฯ) **เก็บในโฟลเดอร์ `docs/catalogs/` ไม่เขียนซ้ำในไฟล์สเปก** สเปกเก็บเฉพาะกติกาและตัวเลขการตัดสินใจของระบบนั้น แล้วชี้ไปที่ catalog
- ทุกแถวใน catalog ใช้รูปแบบเดียวกัน (ดู `CORE_BLUEPRINTS.md` §7) และมีแท็กสถานะ `[ใหม่ · x]`, `[อัปเดต · x]`, `[ทำแล้ว · x]` (x = รหัส Phase) ที่ท้ายแถวหรือท้ายหัวข้อ
- ก่อนทำโค้ด catalog คือแหล่งความจริง พอทำโค้ดแล้ว แถวเปลี่ยนเป็น `[ทำแล้ว · x]` และ `docs/CODE_MAP.md` ชี้ไปไฟล์ข้อมูลในโค้ด **ซึ่งโค้ดเป็นแหล่งความจริงหลักแทน**
- ทุกครั้งที่ปิด Phase ให้ AI ค้นแท็กของ Phase นั้นในเอกสารทั้งหมด เปลี่ยนเป็น `[ทำแล้ว · x]` และรายงานรายการที่ยังค้าง

## 3. กฎเหล็ก 8 ข้อ (ห้ามละเมิดเด็ดขาด)
1. **AI proposes, Engine decides:** โค้ดใน `src/engine/` ต้องเป็น **Pure deterministic functions** เท่านั้น ห้าม import React/DOM, ห้ามใช้ `Math.random()`, `Date.now()`, หรือ `crypto` ในการตัดสินผลเกม (ต้องใช้ `nextRng(state.rngState)` เท่านั้น)
2. **Speed Parity (`x1 === x20`):** การรันเกมด้วย Seed เดียวกันและการตัดสินใจเดียวกันที่ความเร็ว `x1`, `x2`, `x5`, `x20` ต้องได้ผลลัพธ์ตรงกัน 100%
3. **Playable without AI:** เกมต้องเล่นได้ครบทุกฟังก์ชันแม้ปิด AI (`aiMode = 'off'`)
4. **Minor Lock (`isMinor`):** ตัวละครอายุ `< 18` ปี ห้ามเจอเนื้อหาผู้ใหญ่ที่จัดจ้านเกินไป (สถานการณ์สุ่มเสี่ยงได้) และอายุ `< 15` ปี ห้ามทำงานแรงงาน เช่น พาร์ทไทม์ ทำได้แค่งานที่ใช้ความสามารถตัวเอง เช่น เปิดหมวกร้องเพลง, ขายของออนไลน์ (ตรวจซ้ำใน Engine เสมอ) **ตารางกติกาอายุ-งานฉบับเต็มอยู่ที่สเปก `03` §1 (แหล่งเดียว) เอกสารอื่นให้ชี้มาที่นั่น** `[อัปเดต · 3.3.3]`
5. **Single Source of Truth สำหรับเวลา:** กริดตารางแผนชีวิต (`character.planner`) เป็นแหล่งความจริงเดียวที่แปลงเป็น `timeAllocation` 168 ชม./สัปดาห์ ห้ามแก้ชั่วโมง 168 ชม. โดยตรงข้ามกริด
6. **กฎ UI และภาษาไทย:** ข้อความแสดงผลทั้งหมดต้องเป็นภาษาไทยธรรมชาติใน `src/data/uiText.ts` **ห้ามแสดงศัพท์เทคนิคเด็ดขาด** (เช่น T0–T3, RNG, Flag อื่นๆ) และ **ห้ามมีอิโมจิ (Emoji) ในโค้ด UI/Data 100%** (ต้องรัน `npm run check:emoji` ผ่านทุกครั้ง)
7. **ห้ามแตะไฟล์ภาพและ Manifest:** ห้ามลบ แก้ไข หรือเขียนทับไฟล์ใน `public/assets/` และ `sceneManifest.json`
8. **สิทธิ์การอัปเดตเอกสารโดย AI (User-Confirmed Self-Update):** AI สามารถเข้ามาอัปเดต เพิ่มเติม หรือแก้ไขไฟล์เอกสารใน `docs/` (เช่น เพิ่ม/ลด TODO ใน `ROADMAP.md`, บันทึกงานที่ทำแล้วใน `PROGRESS.md`, อัปเดต `DESIGN.md`, `CODE_MAP.md`, `BACKLOG_IDEAS.md` หรือไฟล์สเปกอื่นๆ) ได้ด้วยตัวเองทันที **เมื่อผู้ใช้ตกลงยืนยันแล้วว่าต้องการอะไรเพิ่ม อะไรขาดเหลือ หรือสั่งให้จัดการแก้ไขได้** (แต่ห้ามแก้แผนงานเองโดยพลการหากผู้ใช้แค่ถามปรึกษา)
