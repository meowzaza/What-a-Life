# 05_lifestyle_and_training.md — วิถีชีวิต (พรีเซ็ตตารางเวลา) และการฝึกทักษะ

ใช้กับ: Phase 3.2.1 (ทำก่อน) และวางฐานให้ Phase 3.2.2 (ตารางแผนชีวิตแบบหมวดใหญ่-ย่อย)
เอกสารที่ต้องอ่านคู่กัน: DESIGN.md, 01, 02, 03, 04
กติกาตัวเลข: ค่าทุกตัวในเอกสารนี้เป็น "ค่าตั้งต้นที่ปรับได้" ต้องอยู่ในตาราง data (src/data) ห้ามฝังในโค้ด

## 0. ปัญหาที่แก้ และขอบเขต

ปัญหาที่พบจากการเทส:
1. มีตัวคุมเวลา 2 ตัวชนกัน: ปุ่ม `routine` 5 ปุ่ม กับตาราง 168 ชม./สัปดาห์ ผู้เล่นไม่รู้ว่าอันไหนมีผลอะไร และ DayPlan/ฉากอ่านจาก routine ทำให้ฉากกับข้อความขัดกันได้
2. ตัวเลือกวิถีชีวิตมี 5 แบบตายตัว ไม่เปลี่ยนตามช่วงวัยหรือสถานะ
3. ปุ่ม "งานเสริม" ไม่เช็กอายุ/ไม่ผ่านการจ้างงานจริง จึงอาจได้เงินทั้งที่ไม่มีงาน (รวมถึงเด็ก)
4. ปุ่ม "ติวเข้มอัปสกิลทันที" ให้เลเวลทันที ไม่กินช่องเวลา ไม่มีเพดาน

ขอบเขต Phase 3.2.1 (เอกสารนี้):
- ยุบ `routine` เป็น "พรีเซ็ตวิถีชีวิต" ที่ไปตั้งค่าตาราง 168 ชม. (ตัวจริงตัวเดียว)
- อุดช่องโหว่งานเสริม/โอที/ผู้เยาว์
- เปลี่ยนการฝึกทักษะเป็นขั้นบันได 3 ขั้น กินเวลา กินเงิน มีเพดาน

ไม่ทำใน Phase นี้ (ดูข้อ 8): ตารางแผนชีวิตแบบกริด หมวดใหญ่-ย่อย, ปฏิทินเป้าหมายรายปี, ท่อสมัครงาน, ร้านทำผม, เมนูการกระทำในฉาก

## 1. หลักการ

1. ตารางเวลา 168 ชม. คือตัวจริงตัวเดียว ทุกผล (พลังงาน ความเครียด ความสัมพันธ์ ทักษะ รายได้โอที หลักฐานพฤติกรรม) คำนวณจากตารางนี้เท่านั้น
2. พรีเซ็ต = ทางลัดที่ตั้งค่าตาราง ไม่ใช่ตัวคำนวณที่สอง ผู้เล่นปรับชั่วโมงเองต่อได้ (พรีเซ็ตกลายเป็น "กำหนดเอง")
3. Engine ตัดสินทั้งหมด (pure, seeded, ไม่ใช้ Math.random, ผลเท่ากันที่ x1..x20)
4. ไม่มีของฟรี: ทักษะโตจากเวลา + เงิน + สนามจริง ไม่ใช่จากการกดปุ่ม
5. ล็อกผู้เยาว์ (isMinor) และกฎแรงงาน (03 ข้อ 2) ตรวจใน Engine ไม่พึ่ง UI
6. ทุกการล็อกต้องมีเหตุผลที่แสดงให้ผู้เล่นเห็นและใน "ทำไม?" ได้ และมีทางปลดล็อกบอกไว้เสมอ (กัน soft-lock)

## 2. พรีเซ็ตวิถีชีวิต

### 2.1 กติกา

- พรีเซ็ตเก็บเป็น "ค่าส่วนต่างชั่วโมง (delta)" เทียบกับ "ตารางมาตรฐานของช่วงวัยนั้น" ที่มีอยู่ใน `src/data/timeAlloc.ts` อยู่แล้ว ห้ามเขียนเลขชั่วโมงสัมบูรณ์ เพื่อให้ผลรวมไม่หลุด 168
- ใช้หมวดเวลาที่มีอยู่แล้ว (นอน, งาน/เรียน, สังคม, งานอดิเรก, ครอบครัว, พัฒนาตัวเอง, กลางคืน/ปาร์ตี้) และเพิ่ม 1 หมวด: `sideGig` (งานเสริม) ซึ่งเป็นรายการที่ยกยอดไว้
- ขั้นตอนใช้พรีเซ็ต (deterministic): baseline ของช่วงวัย -> บวก delta -> ปรับให้ผ่าน validator ด้วยลำดับการหักตายตัวต่อไปนี้: งานอดิเรก -> พัฒนาตัวเอง -> สังคม -> ครอบครัว -> กลางคืน (ไม่ต่ำกว่า 0) -> นอน (ไม่ต่ำกว่าขั้นต่ำช่วงวัย) แล้วบวก/หักส่วนต่างให้ผลรวม = 168 พอดี
- ชั่วโมงงาน/เรียนรวมไม่เกิน 48 (กฎเดิม), โอทีต้องไม่เกินที่ JobDefinition อนุญาต
- เมื่อผู้เล่นขยับสไลเดอร์เอง พรีเซ็ตเปลี่ยนเป็น "กำหนดเอง" (customized) ค่าไม่ถูกเขียนทับ
- พรีเซ็ตที่เลือกอยู่ต้องมีผลถึง: ผลรายสัปดาห์, ฉาก/DayPlan (ผ่านชั่วโมงในหมวด), หลักฐานพฤติกรรม, ข้อความ "กำลังทำอะไร"

### 2.3 พรีเซ็ตที่ปลดล็อกตามวัย/สถานะ

| กลุ่ม | พรีเซ็ตที่เลือกได้ | เงื่อนไขพิเศษ |
| --- | --- | --- |
| อายุ 0-5 | ไม่มีให้เลือก | พ่อแม่จัดให้ ไม่แสดงเมนู |
| 6-12 | balanced, study_focus, kid_play, rest_recover | ไม่มีงาน ไม่มีกลางคืน |
| 13-14 | เหมือนข้างบน + friends_only, fitness, homebody, family_first | ไม่มีงาน ไม่มีกลางคืน |
| 15-17 | เหมือน 13-14 + work_and_gig | work_and_gig ใช้ได้เมื่อมีบันทึกงานเสริมที่ถูกต้องตามกฎอายุเท่านั้น (ข้อ 3) ห้ามกะดึก ห้ามกลางคืน |
| 18-19 | ทั้งหมด ยกเว้น workaholic/work_and_gig ที่ต้องมีงานจริง | ปาร์ตี้ใช้ได้เฉพาะสถานที่ที่ผ่านกฎอายุ (pubVisitAge) ส่วนชั่วโมงกลางคืนของ 18-19 ทำได้ตามค่า pubVisitAge |
| 20-59 ทำงาน | ทั้งหมด | workaholic ต้องมีงานประจำ, work_and_gig ต้องมีงานเสริม |
| 20-59 ไม่มีงาน | balanced, skill_grind, social_party, fitness, homebody, family_first, rest_recover | แสดงข้อความ "ยังไม่มีงานประจำ" |
| 60+ | balanced, fitness, homebody, family_first, rest_recover, friends_only | ไม่มี workaholic |

พรีเซ็ตที่ล็อกให้แสดงเป็นการ์ดจาง พร้อมเหตุผลสั้นๆ เช่น "ต้องมีงานเสริมก่อน" ห้ามซ่อนหายไปเฉยๆ

### 2.4 การย้ายเซฟเก่า (routine -> พรีเซ็ต)

| routine เดิม | พรีเซ็ตใหม่ |
| --- | --- |
| balanced / สมดุล | balanced (หรือ study_focus ถ้าเป็นนักเรียน/นักศึกษา) |
| hustle / โหมงาน | workaholic ถ้ามีงานประจำ ไม่เช่นนั้น balanced |
| grind / ซุ่มฝึก | skill_grind |
| rest / พักผ่อน | rest_recover |
| side_gig / งานเสริม | balanced (ไม่มีงานเสริมจริง) พร้อมบันทึกในไทม์ไลน์ว่ากิจวัตรถูกปรับ |

เก็บฟิลด์ `routine` ไว้ใน type เพื่ออ่านเซฟเก่าเท่านั้น (deprecated) ห้ามให้ฟิลด์นี้มีผลต่อเงิน พลังงาน ฉาก หรือ DayPlan อีก

### 2.5 ผลต่อ DayPlan และฉาก

- `dayPlan.ts` เลิกอ่าน `routine === 'hustle' | 'side_gig'` ให้อ่านจากตารางเวลาแทน: โอทีเมื่อชั่วโมงงาน > ชั่วโมงสัญญาของงาน, ช่องงานเสริมเมื่อ `sideGig` > 0 และมีบันทึกงานเสริมจริง
- กิจกรรมช่องเวลาและข้อความหัวฉากต้องไม่ขัดฉาก (กฎเดิมของ 04)
- ถ้าไม่มีงานเสริมจริง ชั่วโมง `sideGig` ต้องเป็น 0 เสมอ ดังนั้นฉากงานเสริมจะไม่โผล่

## 3. กฎผู้เยาว์และงานเสริม (อุดช่องโหว่)

ตรวจใน Engine (ไม่ใช่แค่ซ่อนปุ่ม) ที่จุดเดียวที่ทุกระบบเรียก เช่น `checkSideGigEligibility` / ตัวตรวจใน `timeAlloc.ts` และ `economy.ts`

| อายุ | งานเสริม/พาร์ตไทม์ | โอที |
| --- | --- | --- |
| ต่ำกว่า 15 | ห้ามทุกกรณี รายได้จากงานเสริม = 0 | ไม่มี |
| 15-17 | ต้องมีบันทึกงานเสริมที่ผ่านเกณฑ์ (ในช่วงนี้งานเสริมมาจากระบบงานเดิมที่มี; ท่อสมัครเต็มรูปแบบใน 3.3) นอกเวลาเรียน รวมงาน+เรียน ไม่เกิน 48 ชม. ห้ามกะ 22:00-06:00 | ไม่มี |
| 18+ | ต้องมีบันทึกงานเสริมจริง | ตามที่งานหลักอนุญาต |

- ถ้าค่าตารางเวลา/เซฟเก่ามี `sideGig > 0` โดยไม่ผ่านกฎ ให้ validator ตัดเป็น 0 และบันทึกเหตุผลใน Event Log
- ห้ามมีรายได้จากงานเสริมที่ไม่มีบันทึกงานรองรับ
- ปุ่ม "ว่างงาน/พักหางาน" สำหรับนักเรียน/นักศึกษา: ยังไม่แก้ใน Phase นี้ (ต้องมีเหตุการณ์ยืนยันลาออกจากการเรียน ใน 3.3) ให้ปิดปุ่มไว้พร้อมข้อความ "ต้องยืนยันเรื่องการเรียนก่อน" เพื่อกันการกดพลาด

## 4. ระบบฝึกทักษะ (แทน "ติวเข้ม/อัปสกิลทันที")

### 4.1 ขั้นบันได 3 ขั้น

| ขั้น | เลเวล | แหล่งการโตหลัก | เพดาน |
| --- | --- | --- | --- |
| 1 ฝึกเอง | 0-29 | ชั่วโมง "พัฒนาตัวเอง" ในตาราง (ฟรี) | ฝึกเองโตได้ถึง 30 |
| 2 ลงคอร์ส | 30-59 | ชั่วโมงพัฒนาตัวเอง + "ลงคอร์ส" (เสียเงินรายสัปดาห์) | ฝึกเองฟรีไม่ผ่าน 30 ต้องมีคอร์สที่ active |
| 3 สนามจริง | 60-100 | ชั่วโมงใช้ทักษะจริงในงาน/กิจกรรมที่เกี่ยวข้อง (ข้อ 4.4) | คอร์สอย่างเดียวไม่ผ่าน 60 |

ค่าที่เกิดจากการเรียน/ทำงานตามระบบเดิม (เช่น เรียนในโรงเรียน, ทำงานประจำ) ยังโตได้ตามเดิม แต่ต้องอยู่ใต้ขั้นบันไดเดียวกัน (โรงเรียนนับเป็นแหล่งขั้น 1-2 สำหรับวิชาการ งานประจำนับเป็นสนามจริงของทักษะที่เกี่ยวข้อง)

เซฟเก่า/ตัวละครที่มีเลเวลสูงกว่าเพดานอยู่แล้ว: ไม่ลดเลเวล แต่หยุดโตจนกว่าจะปลดล็อกขั้น

### 4.2 สูตรการโตรายสัปดาห์ (deterministic, อยู่ใน onWeek)

```
gain(skill) = hours_effective × base_rate[source, tier]
              × progress_curve(level within tier)
              × aptitude_mult × trait_mult × age_mult × energy_mult
```

- `hours_effective`: ชั่วโมงที่ลงให้ทักษะนั้นในสัปดาห์ (ข้อ 4.3) สำหรับคอร์สต้องมีชั่วโมงพัฒนาตัวเองขั้นต่ำต่อสัปดาห์ ถ้าไม่ถึงให้ลดผลตามสัดส่วน
- `progress_curve`: ลดจาก 1.0 เป็น 0.5 เชิงเส้นตามตำแหน่งภายในขั้น (ยิ่งใกล้เพดานขั้นยิ่งช้า)
- ใช้ค่าสะสมทศนิยมต่อทักษะ (xp) แล้วค่อยปัดขึ้นเลเวลเมื่อครบ ห้ามปัดทิ้งรายสัปดาห์จนไม่โต
- ไม่มี RNG ในสูตร (ถ้าต้องการสุ่มเล็กน้อยให้ใช้ rng จาก state เท่านั้น)

### 4.3 ตารางค่าตั้งต้น (ใส่ใน `src/data/skillTraining.ts`)

| รายการ | ค่าตั้งต้น |
| --- | --- |
| base_rate ฝึกเอง ขั้น 1 | 0.12 เลเวล/ชั่วโมง |
| base_rate คอร์ส ขั้น 2 | 0.07 เลเวล/ชั่วโมง |
| base_rate สนามจริง ขั้น 3 | 0.02 เลเวล/ชั่วโมง (ชั่วโมงใช้ทักษะจริง) |
| ชั่วโมงขั้นต่ำต่อสัปดาห์เพื่อให้คอร์สเต็มผล | 6 |
| เพดานการโตต่อทักษะต่อสัปดาห์ | +3 เลเวล |

### 4.4 ทักษะรายตัว: ทางปลดล็อกขั้น 2 และขั้น 3

ทุกทักษะต้องมีทางปลดล็อกอย่างน้อย 1 ทางในตาราง data ห้ามมีทักษะที่ตันถาวร (ข้อ 4.5)

| ทักษะ | ขั้น 2 (30-59) | ขั้น 3 (60+) |
| --- | --- | --- |
| ภาษาอังกฤษ | คอร์สภาษา | งานที่ใช้ภาษาอังกฤษประจำ หรือเข้าสังคมกับคนต่างชาติสะสมต่อเนื่อง (ตั้งเป็นหลักฐานผ่านเหตุการณ์/ภายหลัง) |

| ทำอาหาร/ค้าขาย | คอร์สอาหาร | งานร้านอาหาร/ค้าขายจริง |

### 4.5 กันทางตัน (Anti Soft-Lock)

- เมื่อทักษะติดเพดาน ต้องแสดงข้อความบอกวิธีปลดล็อกที่ทำได้จริงตอนนี้ เช่น "ลงคอร์สเพื่อไปต่อ" หรือ "ต้องมีงานสายนี้"
- ทุกทักษะต้องมีทางขั้น 3 อย่างน้อย 1 ทางที่ไม่ต้องรอระบบที่ยังไม่มี (ถ้ายังไม่มีงานรองรับในตารางงานปัจจุบัน ให้บันทึก TODO และแจ้งผู้สั่ง ห้ามเดาเอง)
- ทักษะสายสังคม/สุขภาพ ปลดล็อกขั้น 3 ผ่านกิจกรรมต่อเนื่องแทนงานประจำ (ข้อ 4.4)

### 4.6 การกดฝึกเฉพาะกิจ

- ยกเลิกปุ่ม "ติวเข้มอัปสกิลทันที" ที่ได้ผลทันที
- แทนที่ด้วยการตั้ง "ทักษะที่ฝึก" (โฟกัส 1-2 ทักษะ) และ "ลงคอร์ส" ซึ่งเริ่มมีผลในสัปดาห์ถัดไปตามชั่วโมงจริง
- การเปลี่ยนโฟกัส/เริ่มคอร์สไม่ทำให้เวลาเดินข้ามไปเอง แต่ผลคิดตามเวลาที่เดินจริงเท่านั้น

## 5. UI (แท็บ "ชีวิต" บนมือถือ)

- ส่วน "วิถีชีวิต": การ์ดพรีเซ็ตที่เลือกได้ตามวัย/สถานะ (ข้อ 2.3) แต่ละการ์ดแสดงสรุปสั้นๆ ว่ากระทบอะไร (เช่น "เครียดขึ้นเล็กน้อย เงินเพิ่ม") และปุ่ม "ปรับละเอียด" เปิดหน้าตารางเวลาเดิม (`TimeAllocPanel`) การ์ดที่ล็อกแสดงเหตุผล
- พรีวิวผลก่อนยืนยัน (ใช้ตัวพรีวิวเดิมของ timeAlloc)
- ส่วน "ฝึกทักษะ": รายการทักษะ แสดงเลเวล ขั้น (ฝึกเอง/ลงคอร์ส/สนามจริง) แถบความคืบหน้า โฟกัสได้สูงสุด 2 ปุ่ม "ลงคอร์ส" (เลือก 4/8/12 สัปดาห์ แสดงราคา) และข้อความทางปลดล็อกเมื่อติดเพดาน
- ลบปุ่ม "ติวเข้มอัปสกิลทันที" ออกจากหน้า
- ข้อความทุกอย่างอยู่ใน `src/data/uiText.ts` ห้ามมีศัพท์เทคนิคและอิโมจิ (รัน `npm run check:emoji`)
- ห้ามกล่อง/แผงใหม่บังฉากพิกเซลหลัก ปุ่มเวลาติดขอบจอตามเดิม

## 7. เกณฑ์ตรวจรับ (ตรวจด้วยปุ่ม Dev เป็นหลัก)

1. ตัวละครอายุ 6-14 ไม่มีรายได้จากงานเสริมไม่ว่าทางใด (รวมเซฟเก่าที่เคยตั้ง side_gig)
2. อายุ 15-17 กดพรีเซ็ตงานเสริมไม่ได้ถ้าไม่มีบันทึกงานเสริมที่ถูกต้อง
3. เลือกพรีเซ็ตแล้วผลรวมตาราง = 168 เสมอ และนอนไม่ต่ำกว่าขั้นต่ำช่วงวัย
4. ขยับสไลเดอร์เองแล้วพรีเซ็ตเปลี่ยนเป็น "กำหนดเอง" ไม่ถูกเขียนทับ
5. ไม่มี routine ใดมีผลต่อฉาก/เงิน/พลังงานอีก (ค้นโค้ด: ไม่มีการอ่าน `routine` นอกตัวย้ายเซฟ)
6. ทักษะ 29 -> ฝึกเองผ่าน 30 ไม่ได้ ต้องมีคอร์ส active; ทักษะ 59 -> คอร์สผ่าน 60 ไม่ได้ ต้องมีสนามจริง; ทักษะสังคมผ่านขั้น 3 ได้ด้วยกิจกรรมต่อเนื่องโดยไม่ต้องมีงาน
7. ไม่มีปุ่มที่ทำให้ทักษะเพิ่มทันที
8. seed เดียวกันเล่น x1 กับ x20 ได้ทักษะ/เงิน/พรีเซ็ตเหมือนกัน
9. เซฟ Phase 3.2 เปิดได้และถูกย้ายพรีเซ็ตอัตโนมัติ

ชุดเทสต์: เพิ่มไม่เกิน 1 ไฟล์ 5 ข้อ (ข้อ 1, 3, 6, 8, 9) รันครั้งเดียว ห้ามวนแก้เกิน 1 รอบ ที่เหลือตรวจด้วยปุ่ม Dev
